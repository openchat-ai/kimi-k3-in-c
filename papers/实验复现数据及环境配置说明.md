## 1 平台与运行环境

| 项 | 值 |
| --- | --- |
| CPU | Hygon C86-3G，8 核 16 线程 |
| 内存 | 56 GB |
| 源盘 | 机械盘，近满，挂载于 `/model`（只读，模型权重） |
| 数据盘 | SINKER SEV512THK-CEN NVMe，1 盘 384 GB，ext4 |
| 主机环境 | Windows + WSL2，磁盘分区直挂为块设备（非 VHDX 镜像） |
| 客体内核 | Linux 5.x，x86_64，gcc |
| 构建 | `make -j8`，`-O3 -march=native -fopenmp -pthread` |
| 推理引擎 | 本项目自研纯 C 引擎 `bin/k3` |

**关键环境限制（复现者须知）**

1. **WSL2 后台会话不继承已挂载磁盘。** 通过任务计划程序或后台进程启动的 WSL 会话中
   `/mnt/nvme` 为空目录，必须在该会话内自行挂载，否则引擎报
   `cannot open .../embed/...` 而失败。本项目的运行脚本已内置该挂载步骤。
2. **WSL2 不强制 memory cgroup 限制。** `systemd-run -p MemoryMax=512M` 下真实分配并写入
   1024 GB 的测试进程仍成功（`reports/gateab_ab/test_memcap2.sh`）。
   **故正文原表 3 所依赖的 26 GB 硬内存上限在本平台不可施加**，该表已删除（见第 6 节）。
3. **本平台无硬件 PMU**：无 `cpu` perf 事件源、无 `uncore_imc_*`、无 `/dev/cpu/0/msr`。
   可用观测面为 `/proc/diskstats`、`/proc/vmstat`、宿主 `Get-Counter \PhysicalDisk(*)`、
   引擎自报计数器。**本说明中的一切数据均不依赖硬件计数器。**

## 3 测量纪律（复现者必读）

**本项目的性能类观测量的可重复性远低于直觉，直接影响哪些数字可复现。**

### 3.1 稳定与不稳定

```
字节类观测量（每词元请求数、字节数、每流速率、队列时长）   10 轮逐位一致
s/词元（端到端速度）                              同源码连续三轮跨度 22.5%
```

三例（同源码、同配置、连续三轮）：

```
2026-09-30   65.21  75.62  79.91 s/词元      跨度 22.5%
2026-09-29   76.04  73.39  74.91             跨度  3.6%
v59 二分首点  83.60（与前二者同源码）
```

**结论：不得引用跨时段的绝对速度作对比。**

### 3.2 判定门槛

凡以速度为观测量作配置间对比，须同时满足：

- 同一时段内交错配对重复 ≥ 5 轮
- 配对差 ≥ 10%
- **配对差自身的离散显著小于该效应**（若配对差翻符号，或离散达到其中位，
  判定为 `CANNOT MEASURE`，即本次测量作废）

**`CANNOT MEASURE` 与"无差异"后果相反**：前者是"什么都不能决定"，
后者是"效应已确认小于门槛，可按其他依据决定"。**不得混同。**

完整规程见 `reports/gateab_ab/BENCH_PROTO.md` 第 13、14 节。

### 3.3 探针自检

新探针在长跑前必须短烟测并自检：文件几何取自引擎或文件本身（不猜）、
时钟分辨率已验、短读打印 `errno/offset/length`、stride 与槽数互质、
传给 `pthread_create` 的结构体活过所有线程。**烟测必须调用被测函数本身，
不得复制其逻辑或改写其参数。**

## 6 已知不可复现的部分（如实声明）

**原表 3（L1 替换策略对照）已从稿件删除。** 三条理由：

1. **无源。** 其六个数值（107.27 / 96.35 / 106.52 / 100.17 / 20.99 / 17.44）
   在字节级台账中出现 **0 次**；稿件原表 A.1 将其指向的台账行号
   （`:17, :21, :58-:67`）实为"字节流分类总纲"与 BF8 压缩估算，与策略对照无关。
2. **前提不可施加。** 该对照限定 cgroup 26 GB 硬内存上限，本平台为 WSL2，
   不强制 memory cgroup（见第 1 节第 2 点），该前提无法实现，
   故既不能复现也不能否证。
3. **无上限条件下效应不存在。** 以 {LRU, heat} × {8, 15} GB 四臂各 3 轮复现，
   专家段字节**逐轮一致**（LRU 25.83、heat 25.50 GB/词元），
   即 heat 相对 LRU 仅 **−1.3%**，且 cache 由 8 GB 增至 15 GB 字节完全不变，
   与原表所载 −19% / −32% 不符。因字节列三轮零离散，效应若有 19% 必会显现。

**该节曾支撑的"替换策略是独立于介质落位之外的第二个影响因素"一说随之撤回，
不在稿件摘要与结论中出现。** 稿件 4.5 节保留了完整删除说明，未隐去。

**另有两项如实声明：**

- **速度类观测量的可重复性不足**（3.1 节）。故稿件 4.6 节**不给出**剩余性能差距的
  可达上限，只陈述该差距"非字节所致、亦非设备能力不足"。
- **部分早期探针数据不可用**：曾出现短读被解释为"越界"（`errno` 实为 `EBADF`）、
  槽位数自行推算、探针输出文件竞争导致半数读取静默失败等情况。
  相关结论已撤回，过程记录保留在 `reports/gateab_ab/DAY1/summary.txt`
  与 `FINDINGS.md` 的撤回清单中。

## 7 工具链

```bash
make clean && make -j8          # 构建；产物 bin/k3
make test                       # 单元测试，不需模型权重
objdump -d bin/k3 | grep -c ymm # 应约 1430；若为 323 说明 .o 陈旧、AVX2 退化为 SSE
```

**AVX2 检查为强制项。** 陈旧目标文件会使向量化退化为 SSE 而不报错，
从而使全部速率腰斩。本项目曾依赖该检查发现此类问题。

代码与全部测量脚本：项目仓库，分支 `perf/layer-bundle-preload`。
